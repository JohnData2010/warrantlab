WarrantLab

Scholarly Argument Intelligence

Find the missing reasoning between your evidence and your claims. A browser workspace for PhD and research students writing Information Systems papers. It never rewrites their text.

Status: approved · "WarrantLab" is a provisional working name

What the PRD made concrete

Scope said "Analyse Argument"
Now we know it returns exactly one of three outcomes, plus a separate Analysis incomplete state so a failure is never reported as a clean result.
Scope said "a diagnostic panel"
Now each finding is a Warrant Check (Evidence → Missing warrant → Claim), with at most three findings in text order and no severity ranking.
Scope said "one paragraph in"
Now it accepts up to 3,000 words. Longer text is rejected, never truncated, and the limit drops if long-input tests aren't stable.
Scope said "a section selector"
Now there are 8 planned sections, each enabled only after it passes a four-part validation gate.

The core journey

In words: choose a supported section, then paste up to 3,000 words. Analyse returns one of three outcomes. Edit text returns the original text to revise in your own words, then you analyse again. Success is TC1 revised into TC2, moving from overclaim to no overclaim.

Acceptance criteria

Core behaviour (AC1–AC8)
IDPass condition
AC1The input is unchanged byte for byte. Only the user edits it.
AC2Highlights are exact substrings at verified positions. Ambiguous matches suppress the highlight and show a neutral note.
AC3TC1 highlights the exact span, and the Warrant Check separates the group difference from evidence of a mechanism.
AC4TC2 shows no finding, highlight or warning.
AC5TC3 is neutral insufficient_evidence, with no invented evidence or verdict.
AC6No replacement sentence, rewrite, "apply fix" or one-click correction anywhere.
AC7Empty input is blocked and failures are recoverable. Edits or section changes clear old results but keep the text, and a superseded response is never shown.
AC8The UI says analysis is limited to the supplied text and isn't peer review.
Grounding and evidence (AC9–AC12)
IDPass condition
AC9Any source shown links to a verified publisher page or DOI and states the document type.
AC10Published sources never replace missing user evidence or force an overclaim.
AC11No full-text passages are used at runtime without a version-specific permission check.
AC12Qualitative work isn't required to show causal identification by default.
New in this PRD (AC13–AC20)
IDPass condition
AC13Every finding shows Evidence identified, Missing warrant and Claim, plus What the claim assumes and the Verification status.
AC14At most 3 findings in text order, no severity labels, and a "not an exhaustive review" note when findings were limited.
AC15Over-limit text isn't analysed or truncated. A message appears and the text is kept.
AC16Partial failure shows "Analysis incomplete" with Try again, never a clean result.
AC17Only gate-passed sections can be selected. Others show In development.
AC18TC1 revised into TC2 moves from overclaim to no overclaim.
AC19Neutral states never use amber or warning styling.
AC20The agreed disclosure is shown, and manuscript text isn’t written to browser storage, logs or analytics.

Boundaries

Deferred from the POC
  • Sections that haven't passed the gate (shown as In development)
  • Causal overclaim, unless the development check passes
  • Runtime IS grounding and source cards, until verified methodological notes exist
  • Reliable full 3,000-word analysis, subject to the length gate
  • Copy feedback (only if time allows)
  • Cross-section consistency
Non-goals
  • AI-content detection
  • Rewriting or replacement wording
  • Grammar, style or citation checking
  • Peer-review or publication-readiness scores
  • Judging methodological rigour or validating literature gaps
  • Accounts, saved history, dashboards, integrations
  • Bulk scraping or fine-tuning on journal articles

Open questions

  1. Fixtures still to write: the multi-paragraph case, plus Results and Introduction. Doesn't block the spec.
  2. Interface font: Inter or IBM Plex Sans. Can be decided in the spec.
  3. Resolved: a section change clears results but keeps the text, and late responses are ignored. Operation is in memory only, with no absolute deletion promise.
  4. The AI provider’s retention policy must be verified before any specific privacy claim. To investigate in the spec.
