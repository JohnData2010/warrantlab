WarrantLab — Technical Spec

How the Claim–Evidence Alignment Engine makes academic feedback traceable and abstains when it should

Status: approved

Budget constraint: $0 in additional paid services. Inference runs on the Gemini API Free Tier, with billing off and no paid fallbacks. One adapter file keeps the provider swappable. Because free-tier content may be used by Google to improve its products, the demo uses fictional excerpts only and the app says so.

The engine at a glance

Model callDeterministic codeFailure path → incomplete

In words: the browser sends text and section to the server. Prepare checks the limits and numbers the paragraphs. Pass 1 extracts claims and evidence as verbatim quotes. Code verifies them. Pass 2 judges with the full original text and may add evidence. Code verifies again. Aggregate produces exactly one outcome. Any failure produces "analysis incomplete" instead.

Components

Workspace components/Workspace.tsx
Owns section, text, mode, request, result and analysisKey. A section change or edit clears the result, returns to editing and aborts the request. Responses with a stale key are dropped. Receives maxWords and the section flags as props from the server.

SectionSelector · ManuscriptEditor components/
8 sections, where unsupported ones are disabled and marked In development. A plain serif textarea with a live word count, which blocks text over the limit and never transforms it.
prd › Section Selector and Availability · Text Input and Limits
AnnotatedText components/AnnotatedText.tsx
Renders the original string split at verified offsets. Findings are amber <mark> elements and unassessed claims are never marked. No raw HTML injection. Includes "Original text preserved" and Edit text.
prd › AC1 · AC2
DiagnosticPanel components/DiagnosticPanel.tsx
  • OutcomeNotice: the outcome and the neutral or incomplete notices, with Try again
  • FindingCard: the Warrant Check (Evidence → Missing warrant → Claim), assumptions, why it matters, verification status, and expandable "evidence still needed" and "what to examine"
  • UnassessedSummary: neutral, with a count only when every quote is located
  • PanelFooter: scope limits and the privacy disclosure
prd › Findings and the Warrant Check · Privacy of Unpublished Work
Analysis route app/api/analyse/route.ts
Zod-validated POST {text, section}, checked against the limits again with the shared countWords. Returns AnalysisResponse with no-store. Logs only the id, duration, token usage, outcome and failure stage. Never text.
Pass 1 · Extract lib/engine/extract.ts
The full marked text goes in, and claims (including those with no linked evidence), evidence, and paragraphs_covered come out, all as verbatim quotes. No judging.
Verify lib/engine/verify.ts · lib/text/spans.ts
Checks the schema, then stop_reason = end_turn, then that every paragraph was covered, then locateQuote (exact first, then tolerant of whitespace and quote style only, mapped to original offsets, then disambiguated by sentence). A missing evidence quote counts as fabricated: retry once, then incomplete. An unlocatable claim is kept without a highlight.
Pass 2 · Judge lib/engine/judge.ts
Gets the full original text and the verified extraction. Decides per claim: overclaim, calibrated, cannot_assess or out_of_scope. May re-link evidence or quote new passages, which are all re-verified. Must name the inferential step, separate evidence, claim and warrant, and abstain when information is missing. Never says a study is wrong or didn't test something.
Aggregate lib/engine/aggregate.ts
A pure function with the outcome rules above. Up to 3 findings are chosen by clarity of basis and displayed in text order. Causal verdicts are out of scope while the flag is off. This is the main unit-test target.
Section guidance lib/sections.ts
For each section: id, label, P0/P1, a supported flag set by hand only after the gate passes (with a report link), and 2–4 sentences of guidance fed to both passes. Discussion is enabled first.

Epistemic reliability tests

Run with npm run eval -- --section discussion --runs 3. This uses the real model and consumes Free Tier quota (no charge while billing is off). Reports go to eval/reports/. Fixtures are fictional and labelled synthetic.

  1. Outcome match with the expected outcome
  2. Exact span at the correct offsets
  3. No fabrication: every statistic quoted (p, r, n) appears in the input, and every quote is located
  4. Strong wording ≠ overclaim (TC3 and a strongly worded calibrated variant)
  5. No "untested" claims: banned phrases like "never tested" or "is invalid" don't appear
  6. Irrelevant-edit stability: the same outcome and spans after unrelated wording changes
  7. Repeat consistency across N runs, with an agreement rate reported
  8. Revision pair: TC1 gives an overclaim and TC2 gives none
  9. Cross-paragraph evidence isn't misread as insufficient
  10. No claims ≠ no evidence: a descriptive passage (TC4) gives "no in-scope claims", while a claim without evidence (TC3) stays insufficient
  11. Incomplete processing: a mocked truncated or malformed response gives incomplete
Gate: a section becomes supported only when its overclaim, calibrated and insufficient fixtures pass checks 1–5 and 7 in 3 of 3 runs. Optional: --single-pass baseline comparison.

Failure modes

What breaksWhat the user sees
Free quota used up (429)Analysis incomplete plus a quota hint, with no auto-retry. In eval it's reported as "not run (quota)", never as a pass.
Slow model (two passes, perhaps 10–40 s)"Analysing…" with the two-step explanation. Past the timeout: Analysis incomplete and Try again, with the text kept.
Invented quote, skipped paragraph, truncation, refusalCaught by Verify. One retry for fabrication, otherwise Analysis incomplete.
Highlight can't be locatedThe finding is shown without a mark, with the note "Location could not be marked".
Missing API keyAnalysis incomplete. A configuration hint goes to the server console with no manuscript text.
Edit mid-analysisThe request is aborted and the late response is dropped. The section selector is disabled while analysing.

Decisions and open issues

One useful unknown
Does two-pass actually reason better than single-pass, or only make results more traceable? And is a free Flash-class model good enough at academic inference at all? If it fails the gate, Discussion stays unsupported and the demo says so. Investigation: keep two-pass as the default. If time allows, run the Discussion fixtures with --single-pass and compare false positives, missed cross-paragraph evidence, latency and cost. Also clarified: determinism can't be set, so consistency is measured.
